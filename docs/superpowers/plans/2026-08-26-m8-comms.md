# M8 — Lane COMMS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship §5.11's announcements and two-level notification delivery, §5.12's ICS calendar feeds, and the three surfaces that make a silent push failure visible — the delivery report, the push-disabled banner, and the install-state list the office can phone.

**Architecture:** One fan-out behind `NotificationService.enqueue` — the W5 seam three existing workers already call and M9 will call next. Every message writes one `notification` row plus one `notification_delivery` row *per channel*, so "did it land" is answerable per family. Push transport is a port (`PushSender`) with no FCM dependency, because no FCM credential exists anywhere in this repo; the port, the recording and the report are real, the wire is a holdback. Calendar feeds are unauthenticated token URLs resolved through a plain unscoped `Session` (never `with_all_tenants`, whose caller registry lives in a file this lane does not own), then re-scoped with `use_studio`.

**Tech Stack:** FastAPI · SQLAlchemy 2 · Alembic · pytest · React 19 + TypeScript + Vite · vitest · `@studio/ui` primitives · `@studio/i18n`

**Spec:** [SPEC.md](../../../SPEC.md) §5.11, §5.12, §6.5, §7, §12 · [docs/plan/lanes.md](../../plan/lanes.md) § Lane COMMS — M8 · [docs/plan/milestone-plan.md](../../plan/milestone-plan.md) § W5

## Vocabulary this plan fixes, and which later tasks depend on it

**Notification kinds are dotted, `<group>.<event>`.** The three existing callers already
establish it: `trial.reminder`, `trial.followup`, `trial.no_show`,
`billing.overdue.day3`, `health.declaration_missing`, `health.declaration_renewal`.

**The prefix before the first dot selects the preference group.** A prefix with no mapping is
*ungoverned* and always delivers — §5.11 makes types individually mutable only where the
screen offers a switch, and `trial.*` reaches a lead's guardian who has no settings screen.

| prefix | preference group (i18n `preferences.kind.*`) | mutable |
|---|---|---|
| `session.*` | `session_cancelled` | yes |
| `coach.*` | `coach_substituted` | yes |
| `announcement.*` | `announcement` | yes |
| `event.*` | `event` | yes |
| `billing.*` | `payment` | yes, **except `billing.payment_failed`** |
| `belt.*` | `belt` | yes |
| `attendance.*` | `attendance` | yes |
| `health.*` | `health` | **no — transactional** |
| anything else | — | ungoverned, always delivers |

**M9's at-risk kind is `attendance.at_risk`,** and its payload carries
`{"student_id", "group_id", "contact_person_id", "contact_phone", "missed_count"}`.
`contact_phone` is what the one-tap `צור קשר עם ההורה` dials. This is written into the seam's
docstring in Task 3 so lane REPORTS reads it without asking.

**A muted kind still writes the inbox row, and records the push as `denied`.** The seam
returns `Notification`, not `Notification | None` — `tests/contracts/test_seams.py` asserts
the return type — so suppressing the row is not available. Suppressing the *push* is both
available and correct: §5.11 says the inbox needs no permission and never expires. `denied`
renders as `התראות כבויות`, which is exactly the conversation the office should have with a
parent who turned that type off, and `notification_delivery.error = 'preference'`
distinguishes it from an OS denial for support.

```python
#: §5.11's eight switches, in the order `preferences.kind.*` renders them. A group and not a
#: kind: the trigger table has fifteen rows and grows every milestone, and a parent does not
#: think in `billing.overdue.day7`.
PREFERENCE_GROUPS = (
    "session_cancelled", "coach_substituted", "announcement", "event",
    "payment", "belt", "attendance", "health",
)


class NotificationPreference(UUIDPrimaryKey, TimestampColumns, TenantMixin, Base):
    """§5.11 — 'Every notification type is individually mutable per user, except
    health-declaration and payment-failure notices, which are transactional.'

    **Absence means on.** A row exists only once somebody has changed something, so a new
    guardian receives everything without eight inserts at sign-up, and a group added in a
    later milestone defaults to on for people who never saw it. `enabled` is stored rather
    than a `muted` flag because the screen reads as a switch and a column that inverts
    between the database and the UI is a bug waiting for a hurried reader.

    **`kind_group`, not `kind`.** See PREFERENCE_GROUPS.
    """

    __tablename__ = "notification_preference"
    __tenant_table_args__ = (
        CheckConstraint(
            "kind_group IN ('session_cancelled', 'coach_substituted', 'announcement', "
            "'event', 'payment', 'belt', 'attendance', 'health')",
            name="notification_preference_kind_group",
        ),
        # One answer per person per group. A second row is a second answer, and the fan-out
        # would then depend on which one it read first.
        Index(
            "uq_notification_preference_person_id_kind_group",
            "person_id", "kind_group", unique=True,
        ),
    )

    person_id: Mapped[uuid.UUID] = mapped_column(
        PGUUID(as_uuid=True), ForeignKey("person.id", ondelete="CASCADE"), nullable=False
    )
    kind_group: Mapped[str] = mapped_column(String(20), nullable=False)
    enabled: Mapped[bool] = mapped_column(Boolean, nullable=False, default=True)
```

```python
#: Israel's own rules, from tzdata's `Zion` zone, written out because a VTIMEZONE is what
#: makes a DTSTART mean an hour rather than a number. The EU rule is close and wrong: Israel
#: springs forward on the FRIDAY BEFORE the last Sunday of March (`Mar Fri>=23`), which is
#: what BYMONTHDAY=23..29 with BYDAY=FR expresses, and falls back on the last Sunday of
#: October like everyone else.
VTIMEZONE_ASIA_JERUSALEM = (
    "BEGIN:VTIMEZONE",
    "TZID:Asia/Jerusalem",
    "X-LIC-LOCATION:Asia/Jerusalem",
    "BEGIN:DAYLIGHT",
    "TZOFFSETFROM:+0200",
    "TZOFFSETTO:+0300",
    "TZNAME:IDT",
    "DTSTART:19700327T020000",
    "RRULE:FREQ=YEARLY;BYMONTH=3;BYDAY=FR;BYMONTHDAY=23,24,25,26,27,28,29",
    "END:DAYLIGHT",
    "BEGIN:STANDARD",
    "TZOFFSETFROM:+0300",
    "TZOFFSETTO:+0200",
    "TZNAME:IST",
    "DTSTART:19701025T020000",
    "RRULE:FREQ=YEARLY;BYMONTH=10;BYDAY=-1SU",
    "END:STANDARD",
    "END:VTIMEZONE",
)

JERUSALEM = ZoneInfo("Asia/Jerusalem")


def local_stamp(moment: datetime) -> str:
    """`20261126T170000`, in Asia/Jerusalem, to be paired with `;TZID=Asia/Jerusalem`.

    Converted rather than assumed: a value read back from Postgres is timezone-aware but not
    necessarily in UTC. G3 stores UTC; the VTIMEZONE above is what lets the edge be here.
    """
    return moment.astimezone(JERUSALEM).strftime("%Y%m%dT%H%M%S")


def fold(line: str) -> str:
    """RFC 5545 §3.1: no content line longer than 75 OCTETS, continuations begin with one
    space — and that leading space counts toward the next line's 75, so continuations carry
    74 octets of content.

    Split on encoded bytes and never inside a codepoint. A Hebrew character is three bytes,
    so a character-count fold overruns and a naive byte-count fold produces mojibake in a
    parent's calendar. M7's `app/services/events/ics.py` deferred this here for exactly that
    reason.
    """
    raw = line.encode("utf-8")
    if len(raw) <= 75:
        return line
    chunks: list[bytes] = []
    start, limit = 0, 75
    while start < len(raw):
        end = min(start + limit, len(raw))
        # Back off to a codepoint boundary: continuation bytes are 0b10xxxxxx.
        while end < len(raw) and raw[end] & 0xC0 == 0x80:
            end -= 1
        chunks.append(raw[start:end])
        start, limit = end, 74
    head, *rest = (c.decode("utf-8") for c in chunks)
    return "\r\n ".join([head, *rest])
```

enough. Emit `BEGIN:VCALENDAR`, `VERSION:2.0`, `PRODID:-//studio-manager//feed//HE`,
`CALSCALE:GREGORIAN`, `METHOD:PUBLISH`, `X-WR-CALNAME:{name}`, the VTIMEZONE, then one VEVENT
per item, each line passed through `fold`.
