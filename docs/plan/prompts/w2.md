## Where the project stands

**W1 is code-complete and still `active`.** All twelve pieces shipped (M1.1–M1.12) and
`docs/plan/state.yaml` records them. The wave stays open because its exit gate is external,
exactly as W0's is — see [w1-finish.md](w1-finish.md) § Where the wave actually stands for
what was proved and what was not.

**Do not mark W0 or W1 shipped because W2 has started.** A wave marked done on the strength
of its code compiling is the first lie in a status board, and there is a test asserting that
for W0 specifically.

**Everything is on `feat/w1-m1-identity`, and `main` has none of it** — 36 commits at the
time of writing. That is the first thing the next session fixes, because W2's contract commit
goes on `main` and both lanes branch from it.

## Step 0 — merge W1 into `main`

`main` is 0 commits ahead, so this is a fast-forward. Review before merging anyway: this is
the last moment a whole milestone's diff can be read as one thing.

```bash
cd ~/Desktop/studio-manager
git switch main && git pull
git merge --ff-only feat/w1-m1-identity
./scripts/ci-local.sh            # must exit 0 on main before anything branches from it
git push
```

* **`web/packages/ui/src/setup-wizard/GroupsStep.tsx` and `StudentsStep.tsx`** each name
  their one later owner in a header comment — SCHEDULE and PEOPLE respectively. Neither gets
  a sub-slot; the file header is the seam.

## Step 2 — open the two lanes

[lanes.md §2](../lanes.md) § Wave 2 has the exact commands, and § 3 has the ready-to-paste
opening prompt for each lane and for the review session. Nothing in this document replaces
them.

**Merge order is not a preference.** SCHEDULE merges first because M3 reads sessions, so the
reader lands on a base that already has the writer. Review the first lane's diff *before* it
touches `main`, never after — a bad merge contaminates the other lane's baseline.

## The wave does not close until

**E2E-5** (a schedule change rewrites only future sessions — past sessions and any session
with `is_manually_edited = true` are never overwritten) then **E2E-1a** (registration →
approval → active).
