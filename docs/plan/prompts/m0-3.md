This is M0.3 — the design system. Sequential work on main, no worktrees.

ALREADY LANDED — read them, do not rebuild them:
  - M0.1: the three Vite apps, the PWA install layer, CI (six jobs), and the D2
    TOKEN SEED in web/packages/ui — tokens.css, theme.ts, ThemeProvider.tsx,
    fonts.css with self-hosted Rubik, and HelloProof.tsx. tokens.css already
    carries the D8-corrected light palette and the D7 --belt-ring token. Extend
    that file; do not start a second one.
  - M0.1: web/packages/i18n — nine namespaces × three locales. index.ts is
    authored once and a lane never edits it. he and en and ru/common are now at
    full parity; ru is machine-translated pending a native-speaker review.
  - M0.2: web/packages/ui/src/slots.ts — the seam-4 slot registry, with
    registerSlot / useSlot / clearSlot. SlotEntry is GENERIC, not React.FC<any>:
    no-explicit-any and tsc --strict both reject that, and
    Record<string, unknown> fails too because props are contravariant. Any
    composite screen you build reads from it.
  - M0.2: the whole backend core — tenancy, encryption, audit log, log scrubber,
    tests/invariants/. None of it is yours to touch this session.
  - M0.2: ./scripts/lane-check.sh is the one command. `lane-check.sh core` is
    your check, and it already runs every packages/*/src test file and eslint
    over packages/. Adding a component adds it to that gate automatically.

THE D10 ESLINT RULE ALREADY EXISTS and is proven to fire — web/eslint.config.js
bans marginLeft/marginRight/paddingLeft/paddingRight/borderLeft/borderRight/
left/right in favour of the logical equivalents, and a JSXText rule enforces G4.
Verified in M0.2 by planting a violation and watching lane-check go red. Do NOT
rewrite it. Two things it does NOT yet cover, and should:
  - CSS files. The rule is an ESLint no-restricted-syntax rule over JS object
    properties, so a physical property written in tokens.css or any new .css is
    invisible to it. web/.stylelintrc.json exists and is wired into
    `npm run lint`; add the stylelint rule there.
  - the `inset` shorthand and `float: left/right`.

BUILD:

1. The token layer, in D2's three tiers, extending web/packages/ui/src/tokens.css.
   Brand tokens exist but are not settable in v1 (D1 — logo only). Semantic
   tokens (debt · paid · pending · cancelled · danger · focus ring) and
   structural tokens are NEVER overridable, and a test should assert that a
   studio-supplied brand value cannot reach them.

2. Light and dark as separate token sets. Per D8, #a8a49a and #8f8b82 are
   DARK-MODE-ONLY — they fail AA on the light ground at 2.28:1 and 3.12:1.
   #7a766d is retired outright. #6f6b62 is the floor for any light-mode text
   token. Do not fix this by lightening the ground; the ground is #f7f5f1 by
   design. Write the contrast assertion as a TEST over the token values, not as
   a comment — a ratio in a comment rots the first time someone tweaks a hex.

3. Rubik 300/400/500/600/700, one family, one loading strategy. It is already
   self-hosted and precached by the service worker (§6.1 assumes the font is
   there before a coach walks into a basement). Confirm every weight you use is
   actually in the precache manifest — the sw-precache specs already assert the
   manifest, so extend those rather than writing new ones.

4. Light / Dark / System, user-settable, on both apps (D4). ThemeProvider
   already resolves this; wire it to a real control.

5. The UI primitives artboard 4h defines. BeltBar carries a 1px ring in the
   current foreground colour — #17150f on light, #fffefb on dark — and there is
   NO fill-only variant to reach for (D7, G10). Fill alone makes white invisible
   on light at 1.08:1, black invisible on dark at 1.02:1, and yellow fail even
   the 3:1 non-text threshold at 2.02:1. Assert those three cases.

Use the canvas-porter agent on dashboard artboard 4h — ספריית רכיבים.
decisions.md calls it "the highest-value artboard for the code port, the
intended source for the token and component layer." Do NOT open the .dc.html
yourself; Manager Dashboard.dc.html is ~293 KB of inline styles and will swamp
this session. INVENTORY.md exists for planning — read that instead.

Treat the exported canvas CSS as a VISUAL REFERENCE ONLY. Never copy-paste it —
Manager Dashboard.dc.html carries 14 physical CSS declarations and zero logical
ones, which is the whole reason D10 exists.

The canvas is now CORRECT — the three D9 cuts were applied to the artboards on
2026-08-24 (2b's chat, 7c's weight column, 12f's title). decisions.md's
"Applied vs pending" table reflects that. What you see is what ships.

Every component gets a vitest + Testing Library test rendering it in both he
(RTL) and en (LTR), per §13. Strings come from @studio/i18n — G4 is lint-
enforced in apps/, and packages/ui primitives take their text as props.

CONVENTIONS THIS REPO ENFORCES — match them:
  - Assert behaviour, not source text, wherever behaviour is observable. Where
    only source can be checked, say so in the docstring.
  - Prove a new gate fails before trusting it. M0.1 found three gates that
    passed while checking nothing; M0.2 found three more, including one that
    could NEVER have fired. Plant a violation, watch it go red, revert.
  - ./scripts/ci-local.sh must be green before every push.

Plan first with superpowers:writing-plans, then work the plan task by task:
failing test, confirm it fails, minimal implementation, green, commit.

Exit gate: ./scripts/lane-check.sh core is green, every primitive renders in
both directions and both themes, and the contrast floors from D7 and D8 are
asserted by tests rather than by comments.
